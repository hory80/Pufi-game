# Task for Codex: build and verify the Pufi iOS app

You are working on a Mac with Xcode, in a clone of the GitHub repo `hory80/Pufi-game`.

## What this project is
- `index.html` (repo root) is a finished web learning game for young children ("Pufi – Școala jocurilor"), 12 languages. It is built and maintained by another agent (Claude) and published to GitHub Pages.
- `ios/` is a SwiftUI + `WKWebView` wrapper that bundles that game offline and adds native features through a JS bridge:
  - native text-to-speech (`AVSpeechSynthesizer`, word-by-word karaoke events)
  - read-aloud speech recognition (`SFSpeechRecognizer`, on-device when available)
  - parent-recorded praise (`AVAudioRecorder`, 5 slots)
  - one non-consumable IAP "unlock all" via RevenueCat (entitlement `premium`, product `unlock_all`)
  - parental gate before the Parents panel, localStorage backup in `UserDefaults`
- The Swift code in `ios/` was written without a compiler and has **never been built**. Expect compile errors. Your job is to make it build, run and behave correctly.
- Read `ios/README.md` and every file under `ios/PufiStars/` before changing anything.

## Hard rules
1. **Only change files inside `ios/`.** Never edit `index.html`, `foto/`, `imn/`, `fotbal/` or anything else outside `ios/`. If the web game needs a change (e.g. a bridge call is wrong on the JS side), write it down in your report instead. The JS side of the bridge lives in `index.html` (search for `window.native`, `__nativeSay`, `__nativeKaraoke`, `__micRead`, `__parentsExtra`, `__premium`).
2. Keep the bridge contract unchanged unless it is clearly broken: `window.native.call(cmd, args)` returns a Promise; native events come back through `native.on(evt, fn)`. Commands: `speak, stopSpeak, voiceInfo, haptic, gate, asr.available, asr.start, asr.stop, asr.playLast, rec.start, rec.stop, rec.play, rec.list, rec.delete, iap.status, iap.price, iap.buy, iap.restore, store.get, store.set`.
3. Never commit `ios/PufiStars/WebContent/` (generated by `sync_web.sh`), `*.xcodeproj` (generated by XcodeGen), DerivedData, or any secret. Check `ios/.gitignore`.
4. Kids category: no analytics, no ads, no third-party tracking, external links stay blocked.
5. Do not change the bundle id `ch.hory.pufistars`, the product id or the entitlement name without asking.

## Steps
1. `brew install xcodegen` if missing. `cd ios && ./sync_web.sh && xcodegen`.
2. Build for the simulator from the command line until it is clean:
   `xcodebuild -project PufiStars.xcodeproj -scheme PufiStars -destination 'platform=iOS Simulator,name=iPad (A16)' build` (pick an installed iPad simulator; also build once for an iPhone simulator).
   Fix every compile error and warning that matters. Keep fixes minimal and in the existing style.
3. Run in the simulator and check:
   - the game loads offline (airplane mode / no network) and fills the screen on iPad landscape + portrait and on iPhone;
   - language switch works; speech uses the native voice (`voiceInfo` returns the chosen voice);
   - Reading → Stories → "🎤" read-aloud mode: permission prompts appear with the texts from `project.yml`, words turn green while reading;
   - Parents panel opens only after the parental gate; praise recording: record, play, delete, and praise plays after a correct answer;
   - progress survives an app kill and relaunch (store.get / store.set);
   - IAP: without a RevenueCat key the Debug build is fully unlocked and nothing crashes.
4. If something cannot be tested in the simulator (microphone quality, on-device recognition for Romanian, real purchases), say so in the report. Do not fake results.
5. Signing for a real iPad/iPhone needs Hory's Apple Developer team. If it is not already selected in Xcode, stop and ask him to pick the Team in Signing & Capabilities; do not invent a team id.
